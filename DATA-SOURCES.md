# Display reference data

Snapshot downloaded 28 September 2026. These reference tables and icons are embedded in `index.html`. No extra API or CDN requests are made for airline or aircraft metadata.

Route information was added in build 10 and its transport corrected in app/relay build `2026-09-30.vercel.11`. App build `2026-09-30.vercel.15` adds persistent geographic visits and flight segments, first/last observation times and local CSV/XLSX reporting. Fresh in-area reports enter the route queue before delayed visibility; accepted snapshots persist on their matching recorded segment independently of live cache expiry. Aircraft-only route labels remain on by default. Routine uncertainty, navigation and playback explanations remain in About. Routes use plain airport codes; source credits, unknown values, last-known positions and essential feed errors remain.

- **Airlines/operators:** Virtual Radar Server [standing-data](https://github.com/vradarserver/standing-data), `airlines/schema-01/airlines.csv`, CC0 1.0. 5,904 ICAO prefixes. Matching requires a three-letter prefix, a 1–5 character alphanumeric suffix containing a digit, and a callsign that differs from the supplied registration. This is an inference; it does not identify an aircraft owner or guarantee the operating carrier. Unknown, private-looking and unmatched identifiers are left unknown. Historical or reassigned codes may produce outdated matches.
- **Aircraft types:** the same repository, `model-type/schema-01/*.csv`, CC0 1.0. 2,697 active type codes. Unique names are used directly; common ambiguous codes use broad family labels. Other ambiguous codes retain the reported description or type code. Species, engine type and engine count are bundled from the same snapshot; conflicting attributes are left blank. Helicopter markers require an unambiguous helicopter type; absent metadata is never inferred from an airline.
- **Aircraft silhouettes:** original SVG paths drawn for this app, shared by the wall card and both canvas maps. Curated ICAO type groups distinguish wide-body, narrow-body, regional, business and military jet designs. Consistent species/engine metadata supplies generic jet, turboprop, propeller and helicopter fallbacks. The shapes illustrate categories rather than exact models. VRS species `G` means gyroplane, so it is not treated as a glider; the explicit `GLID` code gets a glider symbol.
- **Flight spectrum colours:** original palette and telemetry mapping added in app build `2026-09-30.vercel.16`. The small bundled OKLab conversion uses Björn Ottosson's [public-domain conversion matrices](https://bottosson.github.io/posts/oklab/). Colour interpolation adds no API/CDN requests. Colours use delayed altitude and vertical rate, with a fixed 0–40,000 ft scale, theme-specific contrast and temporal smoothing. Ground colour follows the feed's ground state, never a terrain-height guess. Missing values use the classic wall colour; reception holds freeze the last colour.
- **Brand icons:** [Simple Icons](https://github.com/simple-icons/simple-icons), CC0 1.0. 15 selected monochrome brand icons; other operators show their ICAO code. Source slugs: airfrance, americanairlines, britishairways, delta, easyjet, emirates, iberia, klm, lufthansa, qatarairways, ryanair, singaporeairlines, turkishairlines, unitedairlines, wizzair. Logos identify inferred operators, not ownership or affiliation. See the bundled disclaimer for trademark considerations.
- **Likely routes:** ADSB.lol's `GET /api/0/route/{callsign}/{lat}/{lng}`, verified against the [provider's route implementation](https://github.com/adsblol/api/blob/main/src/adsb_api/utils/api_routes.py) and live responses on 30 September 2026. This individual endpoint is present in the source but excluded from its OpenAPI schema. The previous documented batch POST returned an empty HTTP 201 response during verification. The relay now sends individual public callsigns and reported coordinates, then accepts only a unique result marked plausible with two distinct valid airports. The app adds its own geography and observation-identity checks. Airport codes, names and cities come from that response. The API identifies its data license as ODbL; the UI attributes ADSB.lol beside route details and in the log/minimalist controls. Availability and quotas remain subject to the provider.

Licenses and upstream credits are in `LICENSES/`. The source repositories contain the current versions. Replacing the bundled tables is an explicit app update; these snapshots do not update themselves.

## Display rules

Build 19 adds [OpenFreeMap](https://openfreemap.org/) vector map data using the [OpenMapTiles schema](https://openmaptiles.org/docs/schema/), derived from OpenStreetMap. The visible attribution includes OpenFreeMap, © OpenMapTiles and © OpenStreetMap. Only visible tiles are requested; their browser HTTP cache is retained. OpenStreetMap raster tiles remain the fallback and selectable street-map source. Map requests go directly to the public map providers, independently of the flight relay. No geographic shapes are manufactured by the app.

The optional daylight atmosphere uses the [NOAA solar-position equations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF), calculated locally from time and the chosen display location. It is a decorative surface treatment, not an aviation or sunrise timing instrument, and makes no weather-service request.

- Aircraft registration and type are shown only when the flight provider supplies them. OpenSky does not include these fields.
- Symbol categories depend on the reported type and can be wrong when the feed or bundled reference data is wrong. Business/private and military designs do not establish ownership or current use. Callsigns, registrations and military flags alone never select a military silhouette. Unknown types use a neutral marker. The normal tracker uses reported ground track and displays a dot when that heading is absent. Wall playback derives a separate display heading from the tangent of its great-circle interpolation path; it does not overwrite reported track in details or exports. Position changes below five metres use the reported heading, or retain the previous display heading when unavailable. Reception holds retain the displayed nose; without any usable movement or heading, the wall marker is a dot. This depicts ground movement, not aircraft yaw or wind-corrected air heading.
- Wall follow lookup can resolve a callsign from recent received observations, then tracks its matched ICAO ID. It does not treat the callsign as a registration or a permanent aircraft identity.
- The 24-hour log records unique stable ICAO IDs actually observed within a regional scope, with their latest callsign and available type/registration. It retains observation timestamps, not response-receipt timestamps. No historical data is fetched or invented. Recording gaps and missing metadata remain limitations; the log is local to this browser.
- Tracker routes are labelled **Route** or **Flight route**, with plain airport codes such as **FRA → LIS**. About explains that a callsign match is not a confirmed flight plan, destination, schedule or booking flight number. Ambiguous, multi-leg, missing or implausible routes are omitted. No arrival time, route progress, flight photograph or synthetic route is generated.
- Route identity combines the stable ICAO ID, callsign and observed flight episode. Callsign changes or reception gaps over 30 minutes start a new episode; out-of-order observations do not change a newer identity. Delayed playback uses the route belonging to its displayed observation. Routes expire from the live cache after ten minutes; negative lookups wait five minutes. Historical sightings may retain the route saved with their flight for their 24-hour retention window, without new historical requests.
- Climbing/descending uses reported vertical rate greater than +150 / less than −150 ft/min. Other finite rates show level; absent rates show unavailable. This is a motion label, not a confirmed flight-plan phase.
- Saved aircraft are browser-local ICAO-identifier bookmarks, limited to 300. The saved filter includes only recent observations within the current area.
- Geographic requests retain the existing providers, rate-limit cooldowns, authentication and deadlines. Follow mode adds single-ICAO lookups using the documented provider endpoints. Mode changes respect the current polling delay.

- **Aircraft-only wall layout:** displays the same delayed observations without geographic tiles. Callsign and barometric altitude are reported values; short arrows show reported track, not a speed prediction. Missing data remain unknown. Available routes show on a third line by default and can be hidden in wall settings. Regional recording uses a fixed exact monitoring footprint established separately from the camera. Zoom/layout changes retain its geometry and history. Flight and route attribution are available in the auto-hiding controls.

## Route lookup behavior

The app submits at most four distinct callsigns per batch, with a minimum 15-second interval between batches. The relay accepts up to eight for compatibility and permits one route batch with at most two individual GET requests per warm function instance. It uses one fixed provider and URL pattern and exposes no general proxy. The whole route batch, including body reading, has a 20-second deadline; the browser deadline is 23 seconds. Valid results survive other callsign failures and timeouts. Provider quotas and access restrictions stop queued work and abort other requests; ordinary per-callsign failures defer only those callsigns when other results are available. Queue, controller, cache and cooldowns are separate from the position providers, so lookup failures cannot stop flight polling or delayed interpolation. About contains specific route errors, status and the global lookup switch.

The current public route endpoint needs no additional account or API key. Its access rules may change; it is a best-effort source. For broader production use, consult the provider's documentation and contact guidance. Local regression and layout verification use controlled upstream responses, not a guarantee of live API availability from a particular Vercel deployment.

The wall display can recover an episode's start from up to eight minutes of recorded in-memory points with the same aircraft and callsign. Unknown/different callsigns and previously closed episodes stop recovery; geographic checks and ten-minute route expiry still apply. This associates an existing route answer with actual buffered observations, without fetching historical routes or predicting positions. Cache capacity remains 512 entries, with valid route answers preserved ahead of unresolved entries when a wider feed is ingested.

## Local sightings and exports

Build 15 stores v2 visits, flight segments, inside position observations, exact area bounds, coverage gaps and frozen reports in IndexedDB. Times use provider position observations, not animation or receipt time. Two outside reports beyond a small margin establish exit; later inside reports establish reentry. Missing signal is a separate session after the configured gap, default five minutes, and is not claimed as a confirmed geographic crossing. Latest unique-aircraft summaries are computed from actual observations in the past 24 hours. Callsign changes preserve earlier segment routes without increasing visit count. Legacy rows retain their known aggregate information, with unknown counts/geometry kept unknown.

Reports use elapsed 24-hour periods and half-open event-time bounds, independent of the rolling display. UTC and explicitly zoned local columns are both exported. CSV includes visit/segment and recording/gap rows, with record type, UTF-8 BOM, quoting and formula-leading text protection. Numeric-looking CSV identifiers receive a text prefix to prevent Excel conversion; XLSX stores identifiers as exact string cells. XLSX is created locally with a small OOXML/ZIP writer, numeric count cells and three sheets, without a third-party writer or CDN dependency. No additional relay service, account or server database is introduced.

The recorder/exporter uses an exclusive browser Web Lock or an IndexedDB lease fallback. Report snapshots and cycle advancement commit together before automatic delivery. Downloads are recorded as requested, not confirmed. Folder saves are marked saved after the stream closes successfully; expired permission preserves the pending report. Storage failures preserve dirty records in memory and are shown in Settings. Collection and delivery resume from existing data; missing flights during inactive periods are never reconstructed. Seven completed requested/saved reports per area and all pending folder reports are retained.

## Wall journey estimates (app build 20)

The distance is the great-circle airport-to-airport distance from validated cached route coordinates, not tracked mileage or remaining distance. It uses a mean Earth radius of 6371.0088 km. Aviation units use the exact 1.852 km/NM conversion. Displayed distances above 100 units round to tens.

Estimated flight time is an app heuristic, not a schedule or ETA. It uses nominal cruise assumptions of 490 kt for wide-body jets, 450 kt for narrow-body/business/generic jets and 440 kt for regional jets, with a 460 kt override for reported B738. A fixed 20-minute climb/descent allowance is added and the result rounds to five minutes. Representative cruise values were checked against EUROCONTROL’s indicative [A320](https://contentzone.eurocontrol.int/aircraftperformance/details.aspx?ICAO=A320), [B738](https://contentzone.eurocontrol.int/aircraftperformance/default.aspx?ICAOFilter=738), [A350](https://contentzone.eurocontrol.int/aircraftperformance/default.aspx?NameFilter=A350) and [E195](https://contentzone.eurocontrol.int/aircraftperformance/details.aspx?ICAO=E195&ICAOFilter=e195) records. Category assumptions and the allowance are our simplified presentation model, not model-specific performance calculations. Wind, routing, taxi, holding and airline schedules are excluded. Current groundspeed is deliberately ignored, including on the ground.

No duration is generated for propeller aircraft, helicopters, gliders, military categories or unknown types. Missing or invalid airport coordinates hide both figures. Figures use the route already bound to the displayed aircraft/callsign episode and clear when that route disappears. No new provider lookup, key or relay feature is required.


## Airport geometry (app build 21)

The Gallery map decodes the `aeroway` layer already included in its OpenFreeMap vector tiles and renders only features classified `runway` or `taxiway`. See the [OpenMapTiles schema](https://openmaptiles.org/docs/schema/#aeroway). Supplied line and polygon vertices are rendered at the existing map projection. No hard-coded airport shape, invented threshold marking, runway edge, pavement width or operational state is inferred. Stroke widths are screen styling. Tile simplification, available features and underlying OSM accuracy limit the detail. Airport surface charts and measured engineering drawings are not supplied by this map.

On 1 October 2026, the current OpenFreeMap dataset (planet version `20260927_080001_pt`) was verified with 28 real tiles around Frankfurt. The four distinct runway references were `18`, `07L/25R`, `07C/25C` and `07R/25L`. The viewport contained 12 clipped runway path fragments and 701 taxiway fragments. These are map features, not counts of separate physical runways or taxiways. Both themes and map-free mode were checked.

Airport styling reuses existing tile requests, timeout/concurrency limits, cache bounds and attribution. It creates no provider or route requests and leaves aircraft playback, marker colours, journey estimates and sightings exports unchanged.
